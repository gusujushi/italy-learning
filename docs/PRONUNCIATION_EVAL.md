# 发音评价：怎么工作，能信到什么程度

在「影子跟读 → 🎤 逐句录音」里，录完音点 **「📊 评价发音」**，程序会把你的录音和这一句的标准音频放在一起比较，给出：

- **听懂度**：本机语音识别（Whisper）把你的录音识别成文字，和目标句逐词对照；
- **逐词判断**：每个词标成「读对了 / 有点出入 / 可能读错 / 可能漏读 / 不够清晰 / 无法判断」——都是识别器的判断，措辞特意用“可能”；
- **节奏与语调对比**：语音时长、音节数、停顿、句尾走向（上扬 / 下降）、节奏相似度，以及音高曲线和能量曲线的叠加图；
- **这一句的发音重点**：只看目标句本身（双辅音、词尾重音、gli / gn / sc、c/g 软硬、r、h……），不管识别结果怎样都列出来，建议对照检查；
- **改正提示**：程序按规则针对中文母语者的常见问题给出的提示；
- **AI 老师点评**（可选）：填了 DeepSeek API Key 时，由 DeepSeek 根据上面的文字和数据写点评、给改正意见。

## 为什么「听」不是 DeepSeek 做的

DeepSeek 的模型是**文本模型**：只接收和输出文字，不能处理音频，也没有语音识别接口。所以分工是：

```
录音 ──→ 本机 Whisper（在你的设备上运行，音频不上传）──→ 识别出的文字 + 每个词的"声学证据"
标准音频 ─→ 同样的识别（用来校准）──┘
                                    └→ 评分 / 逐词判断 / 节奏与语调对比（程序里的规则，不需要联网）
                                    └→ DeepSeek：只收到文字和数字（约 1 KB），写评语、给改正意见
```

不填 API Key 也能用：识别、对比、评分、本地提示都在本机完成；Key 只用来请 DeepSeek 写点评。

## 各部分是怎么算的

**1. 识别（`js/asr-worker.js`）。** 在浏览器的 Web Worker 里运行 Whisper-base（int8 量化，约 76 MB）加 ONNX Runtime 的 WebAssembly 运行时（约 22 MB）——全部放在本站的 `vendor/`、`models/`，不访问外部网址。语言固定为意大利语。同一段录音的识别和打分共用一次编码计算。

**2. 逐词判断（`js/pron-eval.js`）。**

- *文字对齐*：把识别出的文字和目标句逐字符对齐（不看词的切分，`buon giorno` = `Buongiorno`；不看重音符号和标点），每个目标词得到「读出来的比例」。
- *用标准音频校准*：同样的识别也对标准音频做一遍。连标准音频都没被识别准的词（识别器自己的弱点）标成「无法判断」，不计分；其余的词是和标准音频的识别结果**相比**，而不是和"完美"相比。标准音频的识别结果按句子记在本机，同一句只算一次。
- *小词不判断*：1–2 个字母的词（a / il / è / la / di……）识别器常常漏听或写成别的，只有“被听出来了”才算读对，没听出来不判断、不扣分（整句都是小词时照常判断）。这条规则来自下面的真人朗读测试：误标成“漏读”的词全是这种小词。
- *强制解码（声学证据）*：给定目标句，让 Whisper 算出每个词在你的录音里有多"像"（对数概率），和标准音频相比得到 Δ。文字对不上、但 Δ 并不差，多半是识别器听岔了，按「读对了」处理；文字对得上、但 Δ 很差，标成「不够清晰」。整句整体偏低（嗓音、麦克风不同）时按这句的中位数校正，最多校正 1.5。
- *分数*：按字符数加权，是「听懂度」，不是「发音标准度」。

**3. 节奏与语调（`js/prosody.js`，纯计算，不需要识别器）。** 把两段音频都变成 16 kHz，算短时能量、说话的起止、停顿（≥ 0.25 秒的内部静音）、音节数（能量峰）、音高曲线（归一化自相关）和句尾走向；用 DTW 对齐两条能量曲线得到节奏相似度。这些数字都是客观、可解释的，但**不能判断某个音发得对不对**；音节数只是估计，相差 1 以内属于正常误差，不提示。

## 实测与局限（请务必看）

我做了两种测试。**结论先说：它能当“有没有读岔”的提示，不能当发音标准的裁判。**

### ① 合成语音：故意读错一个词（60 句）

取 60 句课文，让语音合成把其中一个词**故意读错**（丢掉词尾元音、读错元音、双辅音读成单辅音等），当作“学习者的录音”，看能不能把读错的词找出来。

| 测试 | 结果 |
| --- | --- |
| Whisper-base（int8）自由识别干净的合成语音，词错误率 | **30%**（它自己就会听错不少词——所以必须用标准音频校准） |
| 只看识别出的文字（不校准、不用声学证据） | 发现率 61–73%，但每个词有 13–21% 的误报——不能用 |
| 现在的做法（标准音频校准 + 强制解码证据）：能判断的读错词里能找出来的比例 | **47%**（23/49）；另有 11/60 个读错的词落在“标准音频也没识别准”的词上，无法判断 |
| 同样条件下，读对的词被误标的比例 | **约 4% / 词**（12/307）；60 句里有 12 句至少有一个误标 |
| 分类型：丢掉词尾元音 | 61%（14/23） |
| 分类型：读错元音 | 55%（6/11） |
| 分类型：**单辅音读成双辅音 / 双辅音读成单辅音** | 18%（2/11）/ 0（0/2，另有 3 个无法判断）——基本发现不了 |
| 分类型：c/g 软硬 | 1/2 |

### ② 真人朗读：母语者把句子读对（22 段）

合成语音的“学习者”和标准音频是同一个声音，偏乐观。所以我又用 [FLEURS](https://huggingface.co/datasets/google/fleurs)（Google，CC BY 4.0）里 22 段意大利语母语者的朗读（6–16 秒，不同的人和麦克风，只用于本地评测，数据没有放进仓库），拿标准音频（课程同一个合成声音）当对照，跑同样的评价流程。他们读的是对的，所以**被标出的词都是误报**：

| 测试 | 结果 |
| --- | --- |
| 读对的句子，得分 | 91–100，中位数 100 |
| 可判断的词里被误标的比例 | **约 4%**（14/394）；只看文字、不用声学证据时是 9–11% |
| 其中误标成“可能漏读”的 | 0 个（加“小词不判断”规则之前有 4 个，全是 a / il / è / i） |
| 至少有一个词被误标的句子 | 9/22——这些是 20 词左右的长句；换算成课文里 7 个词左右的句子，大约每 4–5 句有 1 句 |
| 因“标准音频也没识别准”或“词太短”而无法判断的词 | 约 12% |
| 自由识别的质量 | 差：Whisper-base 对真人录音常常听成别的词（如把 *clima mite* 听成 *climamente*、*Medio Oriente* 听成 *migliore int*）——靠声学证据兜底，但这就是误报的来源 |

这个测试**只能说明误报**：测的是母语者，不是中文母语的学习者；学习者真实读错时它能发现多少，**没有数据**。

### ③ 试过又放弃的：逐词“候选证据”

想法：既然识别器会把读错的词自动纠正，就反过来问——对每个词，生成“丢掉词尾元音”“双辅音读成单辅音”这样的错误拼写，看你的录音比标准音频**更支持**哪一个。

- 合成语音上很漂亮：丢词尾元音的 13 个里 9 个明显胜出，其余 69 个候选里没有一个超过同样的门槛；
- 但真人母语者朗读上，**12% 的候选超过同样的门槛**（丢词尾元音这一类 15%），22 句里 17 句至少误报一个——母语者在连续语流里本来就会弱读词尾元音，这个信号没法区分“弱读”和“没读”；双辅音这一类（3% 误报）在合成语音上本来也没有区分力（1/5）。
- 所以**没有上线**。这也是为什么合成语音的数字不能单独当结论。

### 局限小结

- Whisper 带有很强的语言模型：读错的词它常常**自动纠正**成对的词。例如「piza margherita, per favor」（少一个 z、丢了词尾 -e）的录音，它直接识别成了「Una pizza margherita, per favore.」，满分。所以：
  - **满分只说明“识别器听懂了”，不代表发音标准。** 界面上写的是「听懂度」，也特意提醒了这一点；
  - **双辅音的长短、词尾元音有没有读足、e / o 的开闭口、重音位置**，这个工具基本分辨不出——这些正是中文母语者最常见的问题。所以每一句都会列出「发音重点」清单，请对照着自己听「⇄ 对比原音」，并多找真人反馈；
- 能抓到的主要是：整个词读岔了 / 漏读、读成另一句话、词尾元音明显丢掉、语速和停顿、句尾语调；
- **没有用中文母语学习者的录音验证过**；真实录音（口音、麦克风、环境噪声）下的表现可能和上面不同；
- 分数只作参考，不是考试成绩。

## 隐私

- 录音只在你的设备上解码和识别，**不会上传**，也不保存到磁盘（刷新页面就没了）；
- 发给 DeepSeek 的只有文字和数字（目标句、识别结果、逐词判断、节奏数字），**没有音频**；密钥和接口地址见「设置与计划 → AI 老师」。

## 资源与速度

| 项目 | 说明 |
| --- | --- |
| 体积 | 运行库 + 模型约 100 MB，**不随页面加载**；在「设置与计划 → 发音评价」点下载（或第一次评价时确认下载），之后缓存在本机（`isola-asr-v1`），可以删除。**断网也能评价**（端到端测试里验证过），前提是这一句的标准音频也在本机：先在「设置与计划」点「下载全部音频」，否则会提示去下载 |
| 速度 | 在没有显卡加速的普通电脑上（单线程 WebAssembly）：第一次评价某一句约 10 秒（含识别标准音频，结果会记在本机），再评价同一句约 5 秒；模型加载另需几秒。手机可能慢几倍。只用单线程，因为网页没有跨源隔离，不能用多线程 |
| 内存 | 模型运行时占几百 MB；页面空闲 3 分钟后自动释放 |
| 不支持 | 直接双击打开的本地文件（`file://`，模块 Worker 不能从 file 加载）；不支持 WebAssembly 的旧浏览器。这时仍然有节奏与语调的对比 |
